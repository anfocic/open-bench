# Astro frontend for open-bench

Plan for a fresh Claude session. Self-contained — paste this whole file into the new session as the prompt.

## Goal

Replace the single-file `index.html` at the repo root with an Astro static site under `frontend/`, deployed to Cloudflare Pages on a custom domain. Add per-round permalinks so individual rounds are linkable from Reddit/X with OG preview cards. Keep the existing dark-theme look (matches the repo's hero aesthetic).

## Constraints (read carefully)

- **Same repo, subdir.** `frontend/` lives next to `bench/`, `builds/`, `results/`. Astro reads round data from `../results/reviews/`, `../builds/*/rounds/*/meta.json`, `../bench/config.json` at build time.
- **Static-first.** Pure SSG (`output: 'static'`). No SSR, no server. CF Pages with no build args.
- **Build deterministic.** No GitHub API calls during build — read the local filesystem. The frontend you replace currently uses GitHub trees + raw fetches; that approach was for an unbuilt single HTML file. We have the source tree at build time, use it.
- **Don't change the harness.** No edits to `bench/scripts/*` or `results/judgments/*`. Read-only consumer of the data the harness produces.
- **Delete `index.html` at repo root** as the last step of the migration. CF Pages serves from `frontend/dist/`; the root `index.html` becomes vestigial.
- **No frameworks beyond Astro.** No React/Vue/Svelte islands unless a specific interaction needs it. Vanilla JS islands are fine for the sortable runs table.

## What exists today (read first)

- `index.html` at repo root — single-file static page. Fetches `results/reviews/sandbox-<date>.md` via GitHub API at runtime, renders with `markdown-it@14` from esm.sh, and shows a sortable runs table built from `meta.json` files. Read this file for the data shape, the styling tokens, and the table semantics — port them, don't redesign.
- `bench/config.json` — list of `implementers` (model short-names) and their opencode slugs.
- `bench/tasks/<task>/SPEC.md`, `PROMPT.md`, `JUDGE_PROMPT.md`, `JUDGE_RUBRIC.md` — per-task assets. Currently only `bench/tasks/sandbox/`.
- `builds/<model>/sandbox.py` — current "latest" implementation per model (overwritten each capture).
- `builds/<model>/rounds/sandbox-<date>[-rN]/` — per-run archive. Each contains:
  - `sandbox.py` — model output for this run.
  - `meta.json` — model_wall_clock_seconds, cost_usd, tokens_total, input_tokens, output_tokens, cache_read_tokens, sandbox_py_loc, test_exit_code, started_at, ended_at, model_slug, opencode_version, base_commit, harness, session_id.
  - `test-output.txt` — pytest output for the hidden tests.
  - `transcript.md` — opencode session transcript.
  - `diff.patch` — diff of model edits.
- `results/reviews/sandbox-<date>.md` — aggregated multi-judge review, generated by `bench/scripts/aggregate_judges.py`. Markdown with H2 sections: Scoreboard, Per-judge ranking, Self-bias check, Inter-judge agreement, Per-implementation detail, Cost & efficiency, Judging cost & efficiency, Cross-model observations, Recommendation, Spec changes suggested.
- `results/judgments/` — gitignored. Don't try to read it.
- `README.md`, `ABOUT.md` — keep as-is. Frontend links to them on GitHub.

## Data flow

At build time `src/data/rounds.ts` walks the local filesystem:

```ts
// pseudocode
import { globSync } from 'node:fs';
import path from 'node:path';

const ROOT = path.resolve(import.meta.url, '../../..');

function loadRounds(): Round[] {
  const reviews = globSync(`${ROOT}/results/reviews/sandbox-*.md`);
  const runDirs = globSync(`${ROOT}/builds/*/rounds/sandbox-*`);
  // group by round date (the YYYY-MM-DD prefix; samples like -r2 collapse to the same round)
  // for each round, build:
  //   { date, samples: Run[], scoreboard: parseReview(...).scoreboard, ... }
  // sort newest first
}

export const rounds = loadRounds();
```

`Run` shape mirrors `meta.json`:

```ts
interface Run {
  model: string;     // from path: builds/<model>/rounds/...
  round: string;     // YYYY-MM-DD
  sample: number;    // 1 if no -rN, else N
  wallSec: number | null;
  costUsd: number | null;
  tokensTotal: number | null;
  inputTokens: number | null;
  outputTokens: number | null;
  cacheReadTokens: number | null;
  loc: number | null;
  testExitCode: number | null;
  modelSlug: string | null;
}
```

`parse-review.ts` extracts the markdown sections into structured data (regex over headings + table parsing). Keep it dumb — match `## Scoreboard\n` then read until the next `## `, parse the markdown table rows. The aggregator's output is stable; don't over-engineer.

## Pages

### `/` (index)

- Header: title, tagline, links (GitHub, ABOUT, How it works).
- Lineup table from `bench/config.json`.
- Previous rounds list: one card per round, latest first. Each links to `/round/<date>`. Card shows date, top model + score, model count, total cost.
- Footer.

### `/round/[date]`

`getStaticPaths` returns one entry per round date.

Sections (mostly direct ports of the review.md sections, rendered as Astro components for layout consistency):

1. **Scoreboard** — peer/expert/all medians, hidden-tests, verdict mode.
2. **Run details** — RunsTable island (sortable, all-samples / median-per-model toggle). Pulls from `samples` array baked into the round data.
3. **Self-bias check** — Δ self − peer median per model.
4. **Per-judge ranking** — top-3 picks per judge.
5. **Inter-judge agreement** — variance per impl.
6. **Per-implementation detail** — one block per model with judge breakdown + hidden-test outcomes.
7. **Cost & efficiency** — model-only wall-clock + cost from meta.json medians.
8. **Cross-model observations / Recommendation / Spec changes** — render as raw markdown if the reviewer filled them in, else hide.

OG meta per round: title `open-bench round <date> — <champion> wins`, description with top-line numbers, image generated lazily (skip for v1 — OG default fallback is fine).

### `/about`

Render `ABOUT.md` from the repo root. `astro:content` collection or just import the markdown — same dark theme.

## Components — vanilla JS islands

`RunsTable.astro`: ship the data as a `<script type="application/json">` blob, sort/filter in client-side `<script>`. No framework needed. Steal the sort logic from `index.html`.

Keep islands minimal. Astro's defaults (no JS shipped) for everything else.

## Build + deploy

`astro.config.mjs`:

```js
import { defineConfig } from 'astro/config';
import sitemap from '@astrojs/sitemap';

export default defineConfig({
  site: 'https://<domain>',
  output: 'static',
  trailingSlash: 'never',
  integrations: [sitemap()],
  build: { format: 'directory' },
});
```

Cloudflare Pages settings:
- Production branch: `main`
- Build command: `cd frontend && npm install && npm run build`
- Build output directory: `frontend/dist`
- Environment variables: none (static build)
- Custom domain: attach in Pages dashboard, point DNS at CF nameservers.

Per-round rebuild is automatic: any commit that touches `results/reviews/*.md`, `builds/*/`, or `bench/config.json` triggers a Pages rebuild. No webhook needed.

## Migration steps

1. `mkdir frontend && cd frontend && npm create astro@latest .` — pick "Empty" template, TypeScript strict.
2. Install: `npm i markdown-it gray-matter @astrojs/sitemap` and `npm i -D @types/markdown-it`.
3. Build the file layout above. Wire `src/data/rounds.ts`.
4. Copy styles from root `index.html` into `src/styles/globals.css`.
5. Implement `/`, `/round/[date]`, `/about`.
6. `npm run dev`, smoke-test against the existing round 1 data.
7. `npm run build`, confirm `frontend/dist/` has `round/2026-05-05/index.html` etc.
8. Commit, push, attach CF Pages.
9. Once deployed and verified, **delete the root `index.html`** in a follow-up commit. Update `README.md`'s "Latest round" section to link the live site.
